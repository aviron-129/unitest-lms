## 1. Как устроена работа (процесс)

1. **Один промт = одна задача.** Не объединять. Взял файл `Промты/Промт-NN-*.md` → выполнил → проверил → отметил.
2. **Cline / VS Code / Vercel — НЕ нужны.** AI (я) пишу код прямо в `index.html` в этой папке.
3. **Всегда один и тот же файл** — `index.html`. Ничего не разбивать на отдельные файлы. Код комментировать.
4. **После каждого промта:**
   - проверить синтаксис JS (`node --check` на вырезанном `<script>`);
   - прогнать функциональный тест (DOM-заглушка) — если применимо;
   - отмечать статус в **`progress.md`** и в **`План-этапов.md`** (⬜ → ✅).
5. **Проверка в браузере — обязательна** (F12 → Console). Без неё на 20-м шаге потеряемся.

## 4. Стиль и правила UI (держать во всех промтах)

- Акцент: **`#6366f1`**. Цвета ролей: admin `#8b5cf6`, manager `#3b82f6`, teacher `#10b981`, student `#f59e0b`.
- Скругления 16px (у мелких элементов 12–14px), шрифт **Inter**, glassmorphism.
- Брейкпоинты: **480 / 768 / 1024** (mobile-first).
- **3 языка: uz / ru / en** — любой новый текст добавлять во ВСЕ три языка (объект `translations`).
  Проверять, что ключи одинаковы во всех языках.
- **2 темы** (светлая/тёмная) через CSS-переменные.
- В панели глобальный `.header` скрыт (`body.in-panel`), свои переключатели в шапке панели.
- **Слои (z-index) — держать этот порядок:** `.main-content` (auto/0) < `.app-header` (**120**, `position:sticky` — тоже создаёт stacking-context, иначе выпадашки уходят ПОД контент) < затемнение моб. меню (150) < моб. `.sidebar` (200) < `.test-screen`/`#resultScreen` (500).
- Любой новый dropdown/попап в шапке панели рисовать внутри `.app-header` (тогда он выше контента). Не задавать контенту z-index больше 120.
- **Каркас панели (десктоп):** `#panelScreen` ОБЯЗАН иметь класс `panel-layout` (иначе его `display:flex` не применится и sidebar «уедет» над контентом). Глобальный `<main>` — это экран входа; его правило пишется как `body > main` (НЕ `main {…}`), иначе оно поймает вложенный `<main class="main-content">` и снова сожмёт рабочую область до 1100px. Сброс для панели — `body.in-panel > main` (тоже со `>`, иначе `padding:0` по специфичности перебьёт `.main-content`). `.sidebar` — `position:sticky; top:0; height:100vh; width:var(--sidebar-w)` (264px). `.app-header` — `position:sticky; top:0`. Боковые отступы `.app-header` и `.main-content` считаются ОДНОЙ формулой `max(var(--layout-pad), calc((100% - var(--layout-max))/2))` (контент ≤ `--layout-max:1440px`, края шапки и контента совпадают). Глобальная шапка `.header` в панели скрыта.
- **Попапы/выпадашки делать НЕПРОЗРАЧНЫМИ** (`background: var(--surface-solid)`, без `backdrop-filter`), иначе текст сливается с фоном и читается плохо. `--surface-solid`: светлая `#ffffff`, тёмная `#161a36`. Для рамок попапов — `--surface-border`. (Glassmorphism — только для обычных карточек, не для читаемого текста поверх контента.)

## 10. Как я (AI) проверяю код перед сдачей

Инструменты лежат **в проекте**, в папке `tests/` (jsdom установлен локально в `tests/node_modules`):
- `check.js` — синтаксис JS из inline-`<script>` (эквивалент `node --check`).
- `harness.js` — общий загрузчик `index.html` в jsdom (фейковые таймеры, стабы `localStorage`/`alert`/`confirm`, перехват логов).
- `test15.js`…`test22.js` — функциональные тесты по промтам (93 + 58 + 47 + 42 + 39 + 45 + 26 + 20 проверок).
- `static.js` — паритет ключей переводов (243 × 3), `data-i18n`, дубли `id`, каркас панели, z-index.
- `smoke.js` — все роли × разделы × языки × темы (488 проверок).
- `verify-screens.js` — **проверка по скриншотам** в реальном headless Chrome: 1440/390, light/dark, ru/uz/en,
  заглушки, переполнение, `console.error`, ожидаемые селекторы. Скриншоты — в `screenshots/task<id>/`.
- `run-all.js` — запускает всё и печатает сводку.

Запуск:
```powershell
node tests/run-all.js
node tests/verify-screens.js --task 22
node tests/verify-screens.js --task-json "night-prompts/q1.task.json"
```
